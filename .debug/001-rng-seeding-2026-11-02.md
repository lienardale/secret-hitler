# 001 — RNG seeding: every seed word must reach the first output (2026-11-02)

## Observed

`test/rules/rng.test.ts` expected two seeds differing only in their last word to
give different first outputs. They gave the same value.

## Cause

xoshiro128**'s output is computed from state word `s1` only
(`rotl(s1 * 5, 7) * 9`). `createRng` mixed each seed word into its own state word,
so the first output depended on seed word 1 alone. Games still differed (later
outputs mix all words), but the first draws of the role shuffle were correlated
across seeds sharing a word.

## Fix

`createRng` keeps the per-word mixing (a bijection, so the full 128 bits of seed
entropy survive) and then runs the generator 16 steps before use, which
diffuses every seed word into every state word.

Rejected alternative: hashing the four words into one 32-bit value before
expanding it. That also fixes the test, but leaves only 2^32 possible deals,
small enough for a player to brute-force the deck order from what they can see.

## Check

`npm -w @sh/engine run test -- rng` — "Changing any single seed word changes the
first output".

## Known limitation

xoshiro128** is not a cryptographic generator. Players only see heavily reduced
outputs (sorted hands, roles), so recovering the state is not a practical
attack, but if that ever matters, swap the generator for ChaCha20 behind the
same `rng.ts` interface (the state schema version must then change, see
`migrate.ts`).
